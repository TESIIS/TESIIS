# 區域災害警報

## 使用方式

1. 點地圖工具列的鈴鐺「區域災害警報」。
2. 選擇全國、縣市或鄉鎮。地圖原本已選行政區時會帶入；否則優先開啟第一個關注區域。
3. 可「關注這個區域」，最多保存八個本機快捷區域，關閉分頁後仍保留。
4. 公告卡片顯示原發布單位、發布／生效／到期時間、嚴重程度、影響範圍與官方說明。
5. 開啟「包含近期歷史公告」查看解除、更新與已到期的資料。
6. 「查詢此區避難所」會回到地圖，套用選定行政區，清除前一次不相關的關鍵字、災害條件與指定半徑。

關注區域是裝置上的快捷查詢。警報頁開啟且 App 在前景時約每兩分鐘更新，也可點右上角重新整理或下拉更新。頁面每 30 秒重新判斷時間；從背景回到頁面時立即重判並更新。

警報公告與避難所開設狀態是不同資料。地圖跳轉提供該行政區的避難所查詢，公告中的指示保留原文與發布單位。

## 資料來源與狀態

官方來源：

- [NCDR 民生示警公開資料平台](https://alerts.ncdr.nat.gov.tw/)
- [Atom 清單](https://alerts.ncdr.nat.gov.tw/RssAtomFeed.ashx)
- 清單連結的 `Capstorage/*.cap` 公開文件
- [CAP 1.2 規格](https://docs.oasis-open.org/emergency/cap/v1.2/CAP-v1.2-os.html)

不需要申請金鑰。2026-10-10 已以真實來源核對 Atom 的中文上午／下午時間，以及氣象署強風、高溫、雷雨和水利署解除公告格式；資料條款與來源標示記錄於 [NOTICE.md](../NOTICE.md)。

### 畫面上的狀態

| 狀態 | 意義 |
|---|---|
| 發布期間內 | 在公告提供的生效與到期時間之間 |
| 尚未生效 | 尚未到達該資訊區塊的生效時間 |
| 期限未提供 | 來源沒有提供期限，無法判定到期 |
| 已到期 | 已達到來源提供的到期時間 |
| 已解除／已更新 | 引用此訊息的 CAP 控制公告已將它解除或取代 |
| 最新狀態待確認 | 資料來自裝置快取、伺服器更新失敗、部分資料，或超過更新間隔 |

日期一律以臺灣時間（UTC+8）顯示。資料取得時間與來源清單更新時間分開保留，讀取快取不會刷新原本的取得時間。

「本次來源清單沒有符合條件的公告」只在取得完整、仍在快取有效期間的來源回應時使用。503、資料不完整或沒有裝置快取會顯示無法取得／無法確認，不會轉換成沒有警報。

### 行政區比對

比對來源的 `areaDesc`、`counties` 與 `townships` 欄位，處理台／臺與完整縣市名稱。同語言的多個 `info` 區塊分開保存，避免把一個鄉鎮的嚴重程度套到另一個鄉鎮。

僅能比對到縣市的公告，在鄉鎮查詢中標示「範圍較廣」。無法從文字取得行政區的公告，在全國列表保留，區域查詢另回報其數量。只有多邊形、圓形或數字地碼而缺少可解析行政區文字時，目前不據此推算行政區；請查看原始 CAP 的範圍。

## API

```text
GET /api/alerts
GET /api/alerts?city=臺北市&township=中正區
GET /api/alerts?city=高雄市&history=true&limit=200
```

- `city`：選填，22 縣市名稱，接受台／臺。
- `township`：選填，須一併指定 `city`。
- `history`：`true`／`false`，預設 `false`。目前列表包含期限內、尚未生效及未提供期限的公告。
- `limit`：1～200，預設 200。結果被截斷時 `truncated=true`，`total` 是截斷前筆數。

回應主要欄位：

```json
{
  "success": true,
  "available": true,
  "freshness": "fresh",
  "fetchedAt": "2026-10-10T08:30:00.000Z",
  "sourceUpdatedAt": "2026-10-10T08:00:00.000Z",
  "asOf": "2026-10-10T08:30:00.000Z",
  "refreshAfterSeconds": 120,
  "partial": false,
  "failedDocuments": 0,
  "sourceTruncated": false,
  "unknownRegionCount": 0,
  "data": [],
  "total": 0,
  "truncated": false
}
```

`freshness` 為 `fresh`、`partial` 或 `stale`。無任何可用資料時回 503 與 `available:false`。回應使用 `Cache-Control: no-store`，裝置端的明示降級快取由應用程式管理。

## 更新與快取

- 使用 CAP 的 `sender,identifier,sent` 組合識別訊息，依 `references` 處理更新與解除，也處理引用鏈；不以相同事件名稱直接去重。
- 只處理 `Actual`、`Public` 的 `Alert`／`Update`／`Cancel`，演習、測試、私人訊息不進入公開結果。
- 來源清單包含歷史公告。讀取目前／期限未明公告、近 24 小時資料，以及可能更新或解除目前公告的控制訊息。近期歷史仍受來源清單涵蓋範圍限制。
- 單次最多讀取 128 份 CAP，同時最多六個請求；單一請求五秒、整輪預算十二秒，逾時中止下載。
- Atom 最大 2 MiB、單份 CAP 最大 1 MiB。只下載相同來源主機的 `Capstorage/*.cap`，不自動追蹤 HTTP 轉址。
- 已取得的 CAP 文件依 URL／訊息編號／清單更新時間重用；正常取得來源後快取兩分鐘。失敗或部分資料以三十秒重試間隔減少重複請求。
- 多個使用者同時查詢共用一次來源更新。失敗時保留最後取得時間；每次回應仍重新計算是否已到期。
- 裝置快取依行政區與歷史選項分開，不會拿其他行政區的結果來填補查詢。它使用既有有界請求快取，可能被淘汰；動態警報不會放入長期避難資料包。

## 設定與驗證

一般部署直接使用預設值：

```text
ALERT_FEED_URL=https://alerts.ncdr.nat.gov.tw/RssAtomFeed.ashx
```

Compose 已轉送此變數。自訂代理來源必須提供同一主機下的 `Capstorage/*.cap` 連結。

從 `server/` 手動檢查官方來源：

```bash
dart run tool/check_alert_source.dart
```

此工具只讀取來源並印出摘要，不建立資料快照。正式測試使用合成資料，不依賴當天是否有災害公告。

主要驗證涵蓋時區、缺少期限、過期控制訊息、引用鏈、不同發布者、同語言多區塊、地域未知、部分資料、來源掛住、舊回應競態、快取原始時間、關注區域持久化，以及警報到避難所查詢的操作流程。
